# Epistemology of Prism

The Prism Observatory must distinguish what exists from what is known about it. A claim is not true because it is rendered confidently; it is true only within an explicit knowledge source and evidence boundary.

## Knowledge states

`unknown` means no supported observation exists. `observed` means a direct runtime or repository observation exists. `derived` means the statement follows from an explicit architectural relationship. `verified` means a compiler or validator confirmed it under named constraints. `measured` means a reproducible measurement was recorded. `archived` means the evidence is historical and no longer current. `rejected` means a candidate or claim failed a stated gate. `experimental` means an active investigation has not yet earned a stronger state.

Knowledge state is independent from existence state. A planned ComputeImage can be repository-verified as a schema while remaining unmeasured as an execution artifact.

## How Prism knows

Prism observes through repository evidence, compiler verification, runtime receipts, measurements, architectural derivation, illustrative examples, and research direction. Each source names what it can establish and what it cannot.

## Belief transitions

Every interaction may record a semantic event:

`invariant → transformed → visible → hidden → evidence increased`

The event updates confidence only when evidence supports the transition. Interaction never silently upgrades an illustrative state to a measured state.

## Uncertainty

Unknown, partial, deferred, rejected, and experimental outcomes are valid. Uncertainty is not a visual defect; it is part of the model.

## Receipts

A Receipt records subject identity, observation, knowledge source, constraints, provenance, outcome, and confidence. A receipt is evidence about one observation, not a universal proof of the system.
